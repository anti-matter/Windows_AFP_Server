Personal AFP Server Change Log

Version 2.3.0:
- The server is now a 64-bit (x64) application. 32-bit (x86/Win32) builds are
  no longer supported: the solution and project only define x64 platforms, and
  CI, the SSH dev loop, deploy.cmd, and the WiX installer were updated to
  match. The MSI now installs to Program Files (not Program Files (x86));
  existing 2.2.x installs are major-upgraded in place.
- The vendored OpenSSL 1.1 dependency switched to the official Shining Light
  Productions Win64 build (libcrypto64MT.lib import library +
  libcrypto-1_1-x64.dll, from Win64OpenSSL-1_1_1w); the 32-bit libraries were
  removed.
- Fixed: folders on a share could never be deleted from Windows ("file in
  use"). The char-map stream (Afp_CharMap) reader leaked a file handle
  whenever the stream did not deserialize, and a leaked stream handle pins
  its parent directory. The struct it reads stored the mapping position in a
  size_t, so on x64 it no longer matched the 260-byte streams written by
  32-bit builds and every directory read leaked a handle. The stream now
  uses a fixed, bitness-independent on-disk layout (still readable from
  legacy 32-bit streams), all read paths close the stream (RAII), and
  mapping indexes are bounds-checked.

Version 2.2.4:
- No server code changes. Version bumped to exercise the full clean-rebuild
  and MSI major-upgrade path through the new SSH-driven dev loop
  (winboat-deploy/ssh-dev.sh --msi-install). Deployment tooling for the
  dev/test environment moved from the SMB share-watcher to SSH.

Version 2.2.3:
- The executable's version resource (file properties, about box data source)
  is now generated from version.h; it previously reported a hardcoded and
  stale 2.0.0.0. The MSI product version and the exe file/product versions
  now always match.
- Fixed: uninstalling via msiexec did not deregister the event-log and
  PerfMon providers. The deregistration custom action's condition compared
  REMOVE case-sensitively ("All") while Windows Installer sets REMOVE=ALL,
  so it silently never ran; the comparison is now case-insensitive.

Version 2.2.2:
- Installer rebuilt on the WiX Toolset (AfpServerInstaller\product.wxs): the MSI
  is now fully scriptable (no Visual Studio IDE required) and performs seamless
  major upgrades - installing a new version automatically removes the previous
  one (including legacy 2.1.x/2.2.x Installer Projects installs; the original
  UpgradeCode was carried over).
- The MSI now packages afpServer.man, so event-log/PerfMon registration
  (install.cmd) actually takes effect during MSI installation; it previously
  failed silently because the manifest was not in the package.
- install.cmd now registers/unregisters the providers found next to itself
  instead of only the hardcoded default install path, so custom install
  directories work.

Version 2.2.1:
- Fixed CW library finder info mapping.
- Fixed bug writing empty files after line ending conversion.
- Fixed suspicious use of sizeof() in file name mapping code.

Version 2.1.0:
- Convert line endings in files with extensions set in registry to Unix style (LF) when copied to server.
  Convert back to MacOS (CR) style when copied from server. This allows for near seemless integration with
  Git source control.
- Add UI for above feature to set file extensions for conversion.

Version 2.0.6:
- Implement XOR password encryption for AppleShare IP Browser client.
- Add MacBinary file type support with .bin suffix.

Version 2.0.5:
- Implement FpZzzz.
- Don't show .finf folder from SheepShaver.
- Correctly handle .DS_Store files from OSX.

Version 2.0.3:
- Don't ignore files that start with ".", needed for sharing git repos, for example.
- New implementation for file/folder name character mapping. Solved many issues.
- Fixed bug in Volume Parms that prevented support of drives larger than 4GB.
- Fix bug in buffer checks which caused false failure.
- Hardening by including additional checks.

Version 2.0.2:
- Implement FPSetForkParms. Fixes file corruption when files copied to server using older versions of MacOS (7.x).
- Fixed bug in change notify that could lead to potential crash.
- Fixed bug in FPOpenVolume so parameters are not returned when call fails.
- Other minor bug fixes.

Version 2.0.1:
- New installer (Microsoft Installer Project) to have a more Windows-like installation
- Check file name length when enumerating a directory. Prevent Finder crash.
- Fixed volume parent folder entry in index, use drive letter for path if required.
- FPRead should read INT32 for offset, not UINT32. Also, check for positive value.
- Correctly write char_map to dir/file that are created via Windows explorer.
- Some programs would hang in StdPutFile enumerating a file share (looking for parent of root).
- Fixed critical section bug when unmounting two volumes simultaneously.
